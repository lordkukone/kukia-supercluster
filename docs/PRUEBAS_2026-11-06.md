## 4. LOS 5 FALLOS QUE HUBO QUE RESOLVER

### Fallo 1 — Puerto reservado por Windows

```
E srv start: couldn't bind HTTP server socket, port: 8125
```

No era un puerto ocupado: estaba **reservado por el sistema**. Comprobar:

```powershell
netsh int ipv4 show excludedportrange protocol=tcp
```

Rangos reservados en este equipo:
```
8083 – 8182      12803 – 12902     40671 – 40770
8400             13508             49875 – 49974
50000 – 50059    50060 – 50159     50160 – 50259
50260 – 50359    50576 – 50675
```

**Solución:** usar el puerto **8250**.

**Cómo distinguir "reservado" de "ocupado":**
```powershell
try {
    $l = New-Object System.Net.Sockets.TcpListener([System.Net.IPAddress]::Loopback, 8250)
    $l.Start(); "LIBRE"; $l.Stop()
} catch { "RESERVADO: " + $_.Exception.Message }
```
Si el mensaje es *"socket no permitido por sus permisos de acceso"* → reservado.

---

### Fallo 2 — llama-server huérfano comiendo 5,8 GB

Había un `llama-server.exe` de una prueba anterior corriendo en el i7 ocupando
**5,8 GB de los 8 GB** de la 2070 SUPER.

**Síntoma:** la GPU remota marcaba 6.179 MB usados sin haber cargado nada.

**Solución:**
```powershell
Invoke-Command -ComputerName 192.168.50.2 -ScriptBlock {
  Get-Process llama-server | Stop-Process -Force
}
```
Tras matarlo: **713 MiB**.

---

### Fallo 3 — El RPC es el device 0

`--tensor-split 31,47,21` mandaba el 31 % (8,9 GB) a la 2070 SUPER, que solo
tiene 7,1 GB libres:

```
allocating 13913.72 MiB on device 0: cudaMalloc failed: out of memory
```

**Solución:** `--tensor-split 22,31,47`.

---

### Fallo 4 — `--list-devices` no conecta al RPC

```
llama-server --list-devices --rpc 192.168.50.2:50052
Available devices:
  CUDA0: RTX 5070
  CUDA1: RTX 5060 Ti
```

**No aparece RPC0, pero eso no significa que falle.** Ese comando solo lista
dispositivos locales; no conecta a los servidores RPC.

**La única prueba válida** es lanzar con `-v` y buscar:
```
I cmn common_param:   - RPC0    : 192.168.50.2:50052 (8191 MiB, 7131 MiB free)
```

---

### Fallo 5 — El rpc-server se cae y no vuelve

**Solución:** vigilante que lo levanta en 5 segundos.

```powershell
C:\KUKIA_INFORME\vigilar_rpc.ps1
```

Comprueba cada 5 s que el puerto 50052 escucha. Si no, relanza el `ggml-rpc-server`.

Instalado como tarea programada al arrancar: `KUKIA-RPC-Server` y `KUKIA-RPC-Vigilante`.
